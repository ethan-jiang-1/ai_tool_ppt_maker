# 05 — 迁移 / 导入已有 deck

> Controller: [`playbook/migrate-import.md`](../../playbook/migrate-import.md)
> Legacy maintenance: [`reference/legacy-image2-first-maintenance.md`](../../reference/legacy-image2-first-maintenance.md)

## 三种入口

| 路径 | 适用 | 结果 |
|---|---|---|
| 新 init 后导入素材 | 非 run bundle、文件散乱 | 新 HTML-first deck，素材进入 upstream/backbone/source |
| 旧 bundle 物理整理 | 已有三层结构缺失 | 保留 pipeline 身份，修正目录 ownership |
| markerless -> HTML clean vNext | 旧 whole-page Image2 deck 想迁移 | 原版本不变，发布全新 HTML target version |

不得原地给 markerless source 添加 `production.pipeline`。不得从 `IMAGE PROMPT` 猜 typed body，也不得把旧 style master、provider authorization、gate、reset epoch 或 generated bytes带入 HTML target。

## Clean HTML vNext 合同

1. Agent 选择一个 shipped preset 并运行 `ppt_flow migrate-html <run-dir> prepare --preset <name>`；它只创建当前版本 `_scratch/html-migration/projected-run/` 的 source/override scaffold、palette 和 checklist。
2. Agent 根据 legacy material 编写每张保留页的完整 structured fields，保留可用 stable ID、spoken key 与 speaker note；不得把 `IMAGE PROMPT` 自动转换成 body。
3. bare 或 incomplete `ppt_flow migrate-html <run-dir> preview` 只返回 `preparation_required|authoring_required` guide；按 guide 的唯一下一步修复，且不把它当作 comparison evidence。
4. complete preview 才本地渲染 proposed deck，并给出 exact `plan_hash` 与 `old_side_mode`；`verified-current` 才能显示旧 final-slide pixels，`degraded-missing|degraded-stale` 只显示诊断/placeholder。
5. 用户确认 exact mode/hash 后，Controller 运行 `ppt_flow state <run-dir> --confirm-migration-apply --plan-hash <sha> --old-side-mode <mode>`，由 state owner 原子创建 active apply record。
6. 仅在 confirmation 成功后运行 `migrate-html apply`。apply 在 hidden target 中重新 canonical render；输出必须与 preview 逐项一致，且不能复制 scratch generated bytes。
7. 可见 target 发布后进入 `migration-target-review`，content/visual/delivery review 全部重新进行。

迁移 preview/apply 全程零 provider。用户若想先补齐旧侧证据，另行进入 legacy maintenance 并取得远端授权，不能让 migration 命令代做。

## 旧路径映射

| 旧内容 | 新 owner |
|---|---|
| source Markdown / slide notes | `2_backbone/` + `3_versions/vN/slide-specifications.md` |
| source assets | `2_backbone/visual-style/assets/` 或 version `overrides/` |
| `_build/`、图片、旧 PPTX | 只作迁移输入/对照，不复制成 target authority |
| style master / whole-page prompts | 留在 markerless source version，由 legacy reference 维护 |

## 不可跳过

- inventory/map 先展示再搬运
- 长任务持续给 heartbeat
- candidate/contact sheet 必须可见
- exact plan hash/mode 由 Agent 保存并重放，用户不负责抄写
- crash 后只按 journal owner/age/token matrix 恢复，不手删 journal 或 hidden path
- source、target、receipt 任一漂移都重新 preview

完成迁移并不等于交付完成。target 必须通过当前版本的真实 HTML content/visual gates、Stage 4/5 与 final delivery review。
