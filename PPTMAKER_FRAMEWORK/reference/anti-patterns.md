# ANTI_PATTERNS — Framework Errors

## 1. Generate before the story is ready

Do not spend provider budget before the claim, audience, narrative blocks, and
stable slide IDs are clear. Return to source authoring and validate the Page
Authority receipt first.

## 2. Treat a visual brief as free-form provider instructions

Use the closed `VISUAL BRIEF`, registered identity, reference profile, and page
authority fields. Do not add arbitrary layout controls, text literals, or provider
overrides to source.

## 3. Rebuild raw images for a Framed text-only edit

When accepted raw evidence remains exact, a Framed Text Frame change uses Header
Text & Style Refresh. A Pure display-text change, underlay change, or raw-contract
change uses Generated Image Rebuild. Notes use Notes-Only Refresh.

## 4. Edit `_generated/`

Raw images, final slides, projections, PPTX files, and notes receipts are derived
evidence. Edit source or the owning current input, then rebuild the required
lineage. Never make a manual artifact edit authoritative.

## 5. Treat a structural edit as a current-version refresh

Adding, removing, moving, or reordering slides enters Structural Versioning Path.
Preview first, inspect the stable-ID impact and exact plan hash, then apply the
confirmed transaction. The target receives only target-owned raw debt or permitted
unreviewed materialization.

## 6. Turn readiness into authorization

Credential checks, a live diagnostic, an earlier batch, and raw review do not
authorize a new provider submission. Before each nonzero batch, disclose the exact
operation, stable IDs, profile, and maximum submission count, then record
authorization for that exact plan hash.

## 7. Use completed artifacts as a substitute for review

Raw and delivery evidence each require a human `proceed`, `repair`, or `redirect`
decision when complete. A file existing on disk is not acceptance.

## 8. Invent run-bundle paths

Use the layout owner and the glossary before adding files or directories. Run-bundle
root controls are intentionally strict; `_scratch/` and `_generated/` have distinct
purposes and neither is a replacement source owner.

## 9. Resume a non-v2 run as current production

An explicitly targeted non-v2, partial, hybrid, or corrupt pair is an
`unsupported-protocol/export` hard-stop. Preserve its bytes and use the
owner-issued action; never infer current source, receipt, approval, or artifact
authority from it.

## 10. Treat Git as automatic deck recovery

Git is optional and user-owned. Use visible versions and Structural Versioning Path
for deck evolution. A named Git operation requires explicit user scope.
