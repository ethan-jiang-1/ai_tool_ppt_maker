# Runtime and font research

> Researched 2026-07-17. Primary/official sources only. Version numbers below are observations at that date, not floating requirements.

## Executive recommendation

- Use the `playwright` library (not `@playwright/test`) from Node ESM, pin its exact version in `package-lock.json`, and install only its matching Chromium with an explicit setup command. Do not locate or launch a system Chrome.
- Make Node 22 the repository baseline. It is the oldest Node line in Playwright's current documented support matrix, even though the package metadata's permissive technical floor is still `>=18`.
- Treat browser acquisition as installation, never rendering: render/doctor smoke may launch the installed executable but must not invoke `playwright install` or access the network.
- Bundle OFL-licensed **Source Sans 3** for Latin and **Noto Sans SC** for Simplified Chinese. Prefer upstream-produced WOFF2 when it is a stable, complete artifact; otherwise convert a pinned upstream variable font during repository maintenance and treat that WOFF2 as a Modified Version under the OFL. Never fetch Google Fonts CSS or font shards during render.
- Keep the copyright notice and full OFL 1.1 text with every distributed font family. Record upstream URL/commit or release, source SHA-256, generated-file SHA-256, conversion command/tool version, coverage, and Reserved Font Name status.

## 1. Playwright and Chromium

### Verified facts

1. Playwright's current installation page lists **latest Node 22.x, 24.x, or 26.x** and currently supported desktop/CI platforms as Windows 11+/Server 2019+/WSL, macOS 14+, Debian 12/13, and Ubuntu 22.04/24.04/26.04 on x86-64 or arm64. The npm metadata for `playwright@1.61.1`, observed on 2026-07-17, separately declares `engines.node: ">=18"`. The documented support matrix is the appropriate product-support baseline; the package engine is only an install/runtime syntax floor. [Playwright installation](https://playwright.dev/docs/intro) [npm registry metadata](https://registry.npmjs.org/playwright/latest)
2. The official library example uses ESM `import { chromium } from 'playwright'` and `await chromium.launch()`. This repository can therefore remain ESM without adding a test runner. [Playwright Library](https://playwright.dev/docs/library)
3. Each Playwright release expects specific browser binaries. The official browser guide says browser versions are updated when Playwright is updated and recommends running the browser install command after updating. At the observed npm version, `playwright` depends exactly on `playwright-core@1.61.1`; that installed package's browser registry maps Chromium to revision **1228**, browser version **149.0.7827.55**. These numbers describe 1.61.1 only and must change only with the package lock. [Browsers](https://playwright.dev/docs/browsers) [npm registry metadata](https://registry.npmjs.org/playwright/latest) [Versioned browser registry](https://unpkg.com/playwright-core@1.61.1/browsers.json)
4. `npx playwright install chromium` installs only Chromium. On Linux, `npx playwright install --with-deps chromium` installs the browser plus OS dependencies; `npx playwright install-deps chromium` installs only OS dependencies. [Browsers: install browsers and system dependencies](https://playwright.dev/docs/browsers#install-browsers)
5. Playwright documents platform caches at `~/Library/Caches/ms-playwright` (macOS), `~/.cache/ms-playwright` (Linux), and `%USERPROFILE%\AppData\Local\ms-playwright` (Windows). `PLAYWRIGHT_BROWSERS_PATH` selects a shared/custom path. `PLAYWRIGHT_BROWSERS_PATH=0` performs a hermetic install under `node_modules/playwright-core/.local-browsers`. Playwright tracks clients and may garbage-collect unused browser versions; `PLAYWRIGHT_SKIP_BROWSER_GC=1` disables that cleanup. [Browsers: managing browser binaries](https://playwright.dev/docs/browsers#managing-browser-binaries)
6. Download customization is install-time configuration: `HTTPS_PROXY` supports a proxy; `PLAYWRIGHT_DOWNLOAD_CONNECTION_TIMEOUT` changes download timeout; `PLAYWRIGHT_DOWNLOAD_HOST` replaces the download host globally; browser-specific hosts such as `PLAYWRIGHT_CHROMIUM_DOWNLOAD_HOST` take precedence. Playwright documents these mechanisms for firewalls and internal artifact repositories. [Browsers: firewall/proxy and artifact repository](https://playwright.dev/docs/browsers#install-behind-a-firewall-or-a-proxy)
7. Playwright's CI guide recommends installing browsers/dependencies with the CLI. Its current cache guidance says caching browser binaries is generally not recommended because restoring them does not cache Linux OS dependencies; if caching is used, the cache key must include the Playwright version. [Continuous Integration](https://playwright.dev/docs/ci#caching-browsers)
8. Official Docker guidance recommends pinning the image to a specific Playwright version and warns that a project/image version mismatch can prevent Playwright from locating browser executables. Alpine/musl is not supported by the published Firefox/WebKit builds; the official images use Ubuntu. [Playwright Docker](https://playwright.dev/docs/docker#image-tags)

### Recommendations for this change

- Pin an exact `playwright` dependency through `package-lock.json`; do not use `^`, `latest`, or a separately chosen Chromium revision as the runtime contract. Persist an expected runtime profile derived from the installed package (`playwright` version plus `chromium.executablePath()`/browser registry evidence), and have doctor compare installation to that profile.
- Provide one repository setup entry point that runs `playwright install chromium` on macOS/Windows and documents or invokes `playwright install --with-deps chromium` where Linux privilege policy permits. CI should run the same pinned install after `npm ci`.
- Prefer the standard Playwright cache for user installs and a Playwright-version-plus-OS/architecture cache key in CI only when measured savings justify it. Hermetic `PLAYWRIGHT_BROWSERS_PATH=0` is useful for an offline-prepared installation, but it enlarges/re-couples `node_modules`; do not silently select it at render time.
- Offline operation means the matching browser was installed or restored before going offline. Playwright does not document a render-time fallback installer. For restricted networks, mirror the official browser artifacts through `PLAYWRIGHT_DOWNLOAD_HOST` during setup; test the mirror per supported OS/architecture.
- Launch Playwright's bundled Chromium without `channel` or `executablePath` overrides. Block all page network requests in the future renderer and use only local/data URLs; this makes the render smoke genuinely offline.
- Test the declared support matrix, but phrase cross-platform output as stable geometry/coverage under the pinned profile, not byte-identical pixels across operating systems.

## 2. Redistributable Latin and CJK fonts

### Verified facts

1. **Source Sans 3** is an Adobe family distributed under SIL OFL 1.1. Google Fonts metadata records normal and italic variable fonts, weights 200-900, and Latin, Latin Extended, Vietnamese, Greek, Greek Extended, Cyrillic, and Cyrillic Extended subsets. Adobe's official 3.052 release explicitly ships WOFF2 and its WOFF2 release archive is about **3.85 MB for the release bundle**; Google Fonts' current normal variable TTF is about **646 KB**. [Source Sans 3 metadata](https://github.com/google/fonts/blob/main/ofl/sourcesans3/METADATA.pb) [Adobe Source Sans release 3.052](https://github.com/adobe-fonts/source-sans/releases/tag/3.052R) [Google Fonts directory API](https://api.github.com/repos/google/fonts/contents/ofl/sourcesans3?ref=main)
2. Source Sans 3's copyright notice reserves the font name **“Source”**. Its OFL text permits use, embedding, modification and redistribution, but a Modified Version may not use a Reserved Font Name without permission. [Source Sans license](https://github.com/adobe-fonts/source-sans/blob/release/LICENSE.md)
3. **Noto Sans SC** is distributed under SIL OFL 1.1. Google Fonts metadata records a variable weight axis 100-900, primary script `Hans`, primary language `zh_Hans`, and Simplified Chinese plus Latin/Latin Extended, Cyrillic and Vietnamese subsets. Its current variable TTF in the official Google Fonts repository is about **17.77 MB**. [Noto Sans SC metadata](https://github.com/google/fonts/blob/main/ofl/notosanssc/METADATA.pb) [Google Fonts directory API](https://api.github.com/repos/google/fonts/contents/ofl/notosanssc?ref=main)
4. Noto Sans SC derives from Noto CJK. The official Noto CJK download guide distinguishes full language-specific fonts from region-specific subset fonts and explicitly recommends region-specific subsets when only one region is needed or the deployer is unsure. The official Sans 2.004 release's complete Simplified Chinese subset archive is about **50.1 MB for seven static weights**; the Google Fonts variable TTF is materially smaller because it is one variable regional font. [Noto Sans CJK download guide](https://github.com/notofonts/noto-cjk/blob/main/Sans/README.md) [Noto Sans CJK 2.004 release](https://github.com/notofonts/noto-cjk/releases/tag/Sans2.004)
5. Google Fonts' official CSS service currently exposes Noto Sans SC variable WOFF2 as many `unicode-range` shards (101 URLs were observed for the 100-900 request on 2026-07-17), not one self-contained file. That service is designed for web delivery and is mutable; using it directly would introduce network/version drift into rendering. [Google Fonts CSS API response](https://fonts.googleapis.com/css2?family=Noto+Sans+SC:wght@100..900)
6. OFL 1.1 allows fonts to be bundled with software, including commercial software, provided the font is not sold by itself. Redistribution must preserve the copyright notice and license; Modified Versions must remain under OFL, must respect Reserved Font Names, and must not use author/copyright-holder names for endorsement. Documents produced with the fonts are not forced under the OFL. [Source Sans OFL text](https://github.com/adobe-fonts/source-sans/blob/release/LICENSE.md) [Noto Sans SC OFL text](https://github.com/google/fonts/blob/main/ofl/notosanssc/OFL.txt)
7. SIL's official FAQ explains that format conversion is a modification, so Reserved Font Name restrictions apply; distributing a font file normally requires accompanying copyright/license information. [SIL OFL FAQ](https://openfontlicense.org/ofl-faq/)

### Recommendations for this change

- Latin canonical family: bundle the upstream WOFF2 variable Roman from a pinned Source Sans 3 release, and add italic only if the v1 visual contract actually exposes italics. A single variable Roman avoids multiplying files for 400/600/700/900.
- Simplified Chinese canonical family: bundle Noto Sans SC 100-900. First look for a pinned, upstream-produced complete WOFF2 artifact. If no single complete WOFF2 is published, convert the pinned 17.77 MB variable TTF once during repository maintenance using a pinned `fonttools`/WOFF2 toolchain. Do not concatenate Google Fonts shards, dynamically subset per deck, or fetch fonts during rendering.
- Because TTF-to-WOFF2 conversion is a Modified Version, use a new internal family name that does not contain a Reserved Font Name unless counsel/maintainer review confirms the relevant name is not reserved. Preserve the original family and copyright in provenance metadata; include the original OFL text next to the binaries.
- Budget roughly **sub-1 MB** for one Latin variable face and **approximately 10-18 MB** for one complete Simplified Chinese variable face until the actual WOFF2 is generated and measured. The exact committed size and SHA-256 must become proposal/apply evidence rather than a guessed acceptance threshold.
- Coverage smoke should use a checked-in corpus covering ASCII/Latin accents, punctuation/currency, common Simplified Chinese, CJK punctuation, and required numeric/symbol glyphs. At runtime, wait for `document.fonts.ready`, assert every required `document.fonts.check(...)`, and detect missing-glyph fallback with browser measurement or a font-parser coverage table. Do not treat successful CSS loading alone as coverage proof.
- Default CSS stack should make Noto Sans SC the renderer-selected face for Han text and Source Sans 3 for Latin. Avoid relying on OS fallbacks; their metrics and glyph shapes vary across macOS/Windows/Linux.

## Decisions the proposal should lock

1. Exact Playwright version, matching Chromium identity/revision, install command, supported OS versions/architectures, and cache/mirror policy.
2. Exact font upstream release/commit and SHA-256, canonical local filenames/family names, conversion provenance if any, license file placement, measured WOFF2 size, and accepted Unicode coverage corpus.
3. The distinction between setup (may download/install) and doctor/render (must never install or download).
4. Whether official support is limited to Simplified Chinese in v1. Noto Sans SC does not constitute full Traditional Chinese/Japanese/Korean product support; those require explicit future families and coverage tests.
