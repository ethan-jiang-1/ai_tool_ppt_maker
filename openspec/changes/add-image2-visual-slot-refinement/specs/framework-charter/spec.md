## MODIFIED Requirements

### Requirement: WORKFLOW.md describes the complete agent process

WORKFLOW.md SHALL document Phase 3 as a complete HTML delivery and Phase 4 as an optional post-delivery professional visual-slot refinement. Phase 4 requires explicit human cost authorization and per-page adoption, is never a completion gate, and is distinct from Phase-5 legacy whole-page maintenance. The existing local HTML refresh and structural paths remain provider-free.

#### Scenario: Agent understands the complete default path
- **WHEN** an Agent reads WORKFLOW.md
- **THEN** it understands that fresh decks complete at Phase 3 and may later enter optional authorized Phase 4

### Requirement: Active constitutional guidance matches current runtime behavior

Active framework guidance SHALL agree that new decks default to complete local HTML delivery; optional modern refinement is available only after delivery through explicit authorization and remains a no-text visual-slot capability. No active new-deck path requires credentials, style master, provider work, or whole-page prompt generation. Markerless decks remain explicit Phase-5 maintenance/migration.

#### Scenario: New-deck guidance requires Image2
- **WHEN** an active guide makes Image2 credentials a new-deck prerequisite
- **THEN** coherence validation fails

### Requirement: Framework ownership separates complete HTML delivery from future refinement

The Constitution and Agent Contract SHALL state that MD Controller/human review owns content/visual approval, whether to consider optional professional refinement, exact remote-cost authorization, and per-page adoption; JS owns deterministic HTML rendering/evidence and Phase-4 enforcement of authorized provider/provenance boundaries. No provider adapter belongs to ordinary create/build/iteration. Completing HTML delivery remains a terminal valid user outcome with no refinement node, plan, authorization, or false incomplete state until the user explicitly enters Phase 4.

Active guidance SHALL place complete HTML delivery under Phase 3, optional no-text visual-slot refinement under Phase 4, and markerless whole-page maintenance under Phase 5. Phase 4 SHALL not be described as a renderer choice, a new-deck requirement, or a whole-page generator.

#### Scenario: User ends after PPTX delivery
- **WHEN** HTML PPTX/notes are current and the user declines or does not enter refinement
- **THEN** the workflow is complete
- **AND** state has no pending Image2 execution or authorization

#### Scenario: Maintainer searches for Image2 ownership
- **WHEN** active charter guidance distinguishes modern refinement from legacy maintenance
- **THEN** visual-slot work points to Phase 4 and legacy whole-page behavior points to Phase 5
