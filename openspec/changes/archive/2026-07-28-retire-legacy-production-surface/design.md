## Context

`page-authority-image2-v1` / `image2-page-authority` is the sole current production
protocol for new work. The preceding adoption change proved a bounded, read-only
observer and a hash-bound transaction that can move an intact historical run into a
clean Page Authority target without provider calls or copied delivery evidence.

The repository still exposes the retired HTML-first, whole-page Image2, Header-Lock,
and visual-slot production families through source modules, `ppt_flow`, state/review
helpers, Controller documents, executable inventory, fixtures, and main specs. Those
surfaces are no longer a compatibility requirement. Keeping them routable makes a
second production authority appear to exist and makes the normal regression suite
larger than the current contract warrants.

This change removes that active surface while preserving two things with real current
owners: the bounded legacy observer/adoption bridge, and the browser/font/CSP/timeout/
cleanup primitives used internally by Framed Page Authority composition.

## Goals / Non-Goals

**Goals:**

- Make the normal resolver return one successful current adapter:
  `page-authority-image2`.
- Retain legacy inspection only as a `guide` to provider-free adoption, or as a
  prerequisite-first repair/export `hard-stop` for corrupt pairs.
- Re-home the Framed compositor's runtime and notes primitives behind the Page
  Authority boundary before deleting HTML deck-output modules.
- Remove retired commands, Controller nodes, generated owners, legacy state/review
  records, fixtures, and active documentation.
- Apply the checked-in requirement ledger to every affected main-spec requirement and
  add a mechanical audit for executable/import/help/playbook/spec vocabulary.
- Keep ordinary verification to the core tier plus focused provider-free seams. Image2
  aesthetics remain a human raw-review/pilot decision, not an automated verdict.

**Non-Goals:**

- Changing Page Authority source, raw-generation, review, finalization, or adoption
  semantics beyond deleting the old callers.
- Adding a renderer, visual mode, generic fallback, migration writer, waiver, or
  provider behavior.
- Automatically converting historical source, prompts, pixels, approvals, or
  generated artifacts.
- Deleting the legacy observer, adoption transaction, or protocol-neutral browser
  runtime.
- Running broad E2E or any provider-backed/image-aesthetic regression as routine
  verification.

## Decisions

### 1. One current production route; one bounded historical reader

`resolveRunProductionAdapter` remains the single state/source evaluator for normal
work. Its only successful current result is Page Authority. `inspectLegacyProtocol`
remains the only historical reader: a recognized pair receives the existing adoption
action; malformed, mixed, or unsupported pairs receive one repair/export action. It
never returns a legacy adapter, initializes a provider, reads generated bytes as
authority, or writes state.

This is a net simplification: it deletes per-command legacy dispatch and preserves the
one direct observer already shared by CLI, inspection, and adoption. A generic
compatibility adapter was rejected because it would recreate a second writer and
weaken the source/state pair invariant.

### 2. Extract retained runtime primitives into the Page Authority seam

The Page Authority finalizer needs a deterministic local Framed compositor and the
notes/PPTX delivery helpers. The compositor will own its fixed capture profile,
browser launch, font evidence, network denial, timeout, nonblank/dimension checks,
and cleanup through a Page Authority-private runtime module. Notes parsing/injection
will likewise be consumed through a protocol-neutral/Page-Authority interface.

The old HTML slide contract, renderer, object store, HTML review projection, and
HTML-only output publication are not retained as a public or active import path.
Only the captured runtime guarantees survive. Keeping a thin re-export under the old
HTML production tree was rejected because import and inventory audits could no longer
prove that the historical deck route had disappeared.

The implementation order is deliberately explicit: establish these Page
Authority-private modules and move their named callers before deleting
`03-html-production/`.

| Current source | Retained responsibility | New owner and callers | Delete only after |
| --- | --- | --- | --- |
| `03-html-production/internal/html_render_runtime.mjs` | Pinned-browser capture profile, network denial, font/geometry/nonblank checks, timeout, and cleanup | `04-image-production/page-authority/internal/framed_capture_runtime.mjs`, used only by the Framed compositor | Local Framed capture seam proves the same bounded behavior |
| `03-html-production/internal/page_authority_framed_runtime.mjs` | Receipt-bound Framed markup and final PNG composition | `04-image-production/page-authority/internal/framed_runtime.mjs`, imported by `page-authority/finalizer.mjs` | `finalizer.mjs` no longer imports the HTML production index |
| `03-html-production/internal/notes_injection.mjs` | Page Authority source-note extraction and final-PPTX notes injection | `04-image-production/page-authority/internal/notes_runtime.mjs`, imported by `page-authority/operations.mjs` and `page-authority/notes.mjs` | Both callers no longer import the HTML production index and their final-lineage tests pass |

The moved files expose only the existing receipt/evidence inputs. They do not keep a
generic HTML rendering, source-contract, or output-publication API. This gives the
retirement audit a simple invariant: current Page Authority imports never cross an
HTML production path, while the retained browser and PPTX primitives remain local
and provider-free.

The notes row is a helper extraction, not a file move: retain only
`extractNoteRecordsFromMarkdown` and `injectNotes` (and their minimal protocol-neutral
dependencies). The retired Stage 5 CLI, HTML receipts, legacy source validation, and
whole-page assembly helpers in that source file are deleted with the old route.

### 3. Collapse state, review, and CLI surface onto Page Authority evidence

Raw authorization, raw-review acceptance, final manifest/projection, PPTX/notes, and
delivery review remain owned by the existing Page Authority modules and state owner.
HTML content/visual review, Header-Lock review, whole-page manifests, refinement
attempts, and their recovery controls are removed. `ppt_flow` retains shared command
names only for the Page Authority lifecycle plus structural/version, inspection, and
explicit adoption/repair controls. A recognized historical run reaching a shared
command stops at the adoption diagnostic before work. Legacy-only commands, flags,
help entries, and approval choices are absent rather than hidden behind a fallback.

No state migration is written for historical runs. The observer sees source/state
bytes read-only; adoption creates the clean target through the existing transaction.
This preserves the hard-stop invariant for identity, integrity, authorization, and
recovery.

### 4. Controller and documentation describe authority/invalidation, not modes

Active playbooks, `COMMANDS.md`, Charter, BOOTSTRAP, layout maps, examples, and script
inventory describe per-slide Pure/Framed Page Authority work, local Framed refresh,
Pure raw debt, notes-only refresh, structural versioning, and bounded adoption. Old
HTML-first, whole-page, Header-Lock, and visual-slot routes occur only in explicitly
labeled historical observer/migration context.

The MD Controller remains the workflow authority. JS owns resolver/state/diagnostics
and does not replace playbooks with a second routing model.

### 5. Mechanical retirement audit, not broad end-to-end replay

A focused contract test audits active executable registrations, literal imports,
public CLI help, Controller manifests/playbooks, and main-spec Requirement blocks
against a narrow historical allowlist. The checked-in ledger is the requirement-level
disposition record. The audit rejects an unclassified active legacy route; it does
not try to score generated images or execute old pipelines.

Verification is tiered:

| Layer | Evidence | Run policy |
| --- | --- | --- |
| Unit/contract | resolver closure, Page Authority runtime imports, no retired entrypoints | affected files |
| Core regression | framework structural and fast unit suites | normal checkpoint |
| Mocked E2E | one public journey with fake external provider/adapter boundaries | selected `test_mock_*` test; never broad |
| Local render lifecycle | Canvas/PPTX/notes/subprocess evidence with a local fake provider response | not retained as an automated test asset; inspect output only when separately authorized |
| Real E2E | real provider or other external service | explicit `test_real_*` path plus `PPTMAKER_RUN_REAL_E2E=1`, release/environment-health only |
| Image quality | raw review or separately authorized pilot | human-only |

This replaces broad historical route coverage with direct absence checks and retains
only the provider-free adoption journey that proves the compatibility boundary.

### 6. Delta specs remove exact legacy clauses and add concise current contracts

The checked-in ledger is the authority for the 258 requirement titles and their
`Replace` / `Retire` / `Collapse` / `Keep` disposition. The old clauses are largely
incompatible with the current protocol, so this change encodes every non-`Keep` row
as an exact-title `REMOVED Requirement` with a reason and migration target. Each
affected capability also has a concise Page Authority `ADDED Requirement` where it
retains a current responsibility. This avoids copying a legacy requirement body into
a nominal `MODIFIED` block that would preserve retired semantics after archive.

`Keep` rows are not redefined by this change: their accepted main-spec text remains
the contract, and the audit maps each to an existing or added focused regression.
The retirement audit checks title existence before implementation, then checks the
archived main-spec diff for: no active old requirement, one current replacement owner
for each removed `Replace` row, only the observer for each `Collapse` row, and test
coverage for each `Keep` row.

## Risks / Trade-offs

- **A retained Framed dependency is deleted with the HTML route** -> extract it first,
  change the finalizer to the new owner, and test font/network/cleanup/local capture
  before deleting callers.
- **A stale document or help entry advertises a retired route** -> contract audit
  scans active sources and public help, with historical fixture exceptions named
  explicitly rather than hidden by a broad ignore.
- **A historical run loses a route before adoption is available** -> preserve and test
  the existing observer/adoption transaction before removing production adapters.
- **Test deletion removes useful protection** -> replace slow legacy route tests with
  focused absence/ownership tests; retain current Page Authority and adoption tests.
- **Main specs become inconsistent after deletion** -> use the retirement ledger as a
  release gate and review the merged main-spec diff before archive.
- **A broad legacy requirement is removed without a current replacement** -> exact-title
  removal records name their target owner, and the audit rejects a missing Page
  Authority contract for a `Replace` row.

## Migration Plan

1. Add current-only delta requirements and record the ledger disposition audit.
2. Move Framed capture and notes dependencies behind Page Authority; prove the local
   runtime still rejects font/runtime/network/geometry failures.
3. Replace current CLI/resolver/controller/documentation imports and remove retired
   executable modules, state/review helpers, generated owners, and fixtures.
4. Synchronize main specs, Charter, playbooks, inventories, and source-to-test
   ownership with the current implementation.
5. Run focused provider-free verification and strict OpenSpec validation. Archive only
   after the normal resolver, audit, and main-spec review all show one current route.

## Verification Budget

The project declares `npm test` as the protected core tier through
`tests/contracts/run_development_verification.mjs`; it is required at ordinary
checkpoints. The retirement change additionally selects only focused static and
provider-free tests for the changed seams: CLI return/help audit, architecture and
source-to-test ownership, resolver/inspection/adoption observer, the new retirement
surface audit, and a local Framed runtime test when its runtime module moves.

The deterministic mock legacy adoption journey runs only if this change modifies the
observer, adoption transaction, or its CLI boundary. A fake external provider does
not make Canvas/PPTX/notes/subprocess work a lightweight journey: those long local
lifecycle tests are removed rather than retained in another tier. The complete `tests_e2e/` sweep, a real provider journey,
and any Image2 aesthetic comparison are not pre-apply or ordinary implementation
checks. Real E2E requires an explicit later release or environment-health decision,
not a task checkbox in this change.

A published Page Authority target is not rolled back into a historical production
mode. If this repository change itself must be rolled back, restore the prior source
revision; individual historical runs remain byte-preserving until they are explicitly
adopted.

## Open Questions

None. The existing Page Authority contract and the preceding adoption bridge define
the retained boundaries; this change removes the duplicate surface rather than
introducing another compatibility form.
