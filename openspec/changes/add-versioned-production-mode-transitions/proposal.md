## Why

`add-production-mode-and-image2-primary` made production intent authoritative per run version and
released `image2-only` as the default flow.  It intentionally refuses an in-place switch between the
HTML and whole-page Image2 pipelines, so a user who changes page authority after work has started has
no complete, recoverable path today.

This change adds that path through a clean vNext transaction.  Its purpose is safe mode/version
transition, not HTML visual improvement: an HTML target must satisfy the existing valid, runnable HTML
contract and its current delivery process, but this change does not score, compare, or improve HTML
visual quality.  Image2-primary retains its existing artifact-quality, provenance, authorization, and
review requirements.

## What Changes

- Add one state-owned, exact-plan-hash transition protocol for cross-pipeline
  `image2-only <-> html-only|html-then-image2` requests: prepare authored target inputs, preview the
  proposed clean target, obtain an explicit human confirmation, publish vNext, then register only the
  target version's mode after its source contract is verified.
- Generalize the existing Image2-to-HTML migration into a mode-selected HTML target path, preserving
  the existing source/target isolation, no-replace publication, recovery, and target-local evidence
  rules.  HTML is accepted here as a working current-contract path; no new visual-quality rubric,
  parity requirement, renderer-quality work, or HTML style-master implementation is introduced.
- Add the reverse HTML-to-Image2 transition path.  It creates an explicitly authored whole-page Image2
  candidate and a clean markerless vNext; it never infers Image2 prompts, assets, or quality evidence
  from HTML source, HTML pixels, or generated artifacts.
- Make CLI and controller entry/resume expose the nearest transition checkpoint and preserve the source
  version, active evidence, candidate work, and audit history.  A decline, collision, stale plan,
  journal conflict, or recovery failure leaves current mode/version authority unchanged.
- Keep target evidence attributable: no source approvals, final reviews, provider authorization,
  generated bytes, or refinement evidence becomes target authority.  The target follows its selected
  mode's existing completion rules; Image2 targets retain normal pilot/review/authorization quality
  controls, while HTML targets use only their existing contract and human delivery gates.
- Update natural-language guidance and constitutional terminology so a cross-pipeline request routes to
  the versioned transition workflow rather than an in-place state edit or a permanent refusal.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `node-specification`: Define the authoritative cross-pipeline transition state, exact confirmation,
  source/target preservation, handoff, and recovery semantics.
- `cli-surface`: Define the closed public transition grammar, typed diagnostics, and return contracts.
- `playbook-execution`: Route controllers through prepare/preview/confirm/apply/resume without forging
  node completion or silently replacing active work.
- `run-bundle-management`: Publish clean target versions from mode-specific authored candidates and
  preserve no-replace, receipt, registration, and recovery invariants.
- `pipeline-orchestration`: Keep the HTML and whole-page adapters isolated while materializing the
  target through its selected pipeline.
- `commands-reference`: Route user transition intent to the safe versioned path and distinguish it from
  ordinary refresh or structural versioning.
- `framework-charter`: Align active guidance with the completed cross-pipeline transition capability
  and state that HTML visual quality improvement remains a later concern.

## Impact

- Affects the framework-maintenance surface under `PPTMAKER_FRAMEWORK/`, `openspec/`, `tests/`, and
  `tests_e2e/`; it does not treat production `deck_*` data as a framework fixture.
- Extends the existing state/CLI/controller protocol but does not add a second mode authority, a generic
  state editor, an in-place cross-pipeline switch, a provider bypass, or a new renderer dependency.
- Cross-pipeline requests are `confirm` only at exact target-plan acceptance and any existing
  chargeable Image2 boundary.  Missing identity, stale confirmation, collision, journal/CAS conflict,
  or invalid provenance remains a `hard-stop` protecting version identity and attributable work; the
  Agent may perform bounded prepare, validation, recovery, and rerun mechanics.
- The transition path consolidates routing into the existing state owner and selected adapter, with
  prerequisite-first diagnostics and one recovery checkpoint.  It intentionally adds no HTML quality
  validator, score, retry loop, visual parity gate, or style system; those belong to a later HTML
  quality change.
