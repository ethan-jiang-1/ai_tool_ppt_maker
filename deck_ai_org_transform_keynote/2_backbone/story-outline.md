# Story Outline

## Central Claim

AI 转型不是把 AI 加到原来的组织上，而是让个人能力跃迁进入新的工作回路，再被业务流程和组织机制接住，最终沉淀为可持续的组织能力。

## Audience Outcome

听众应完成一次视角转换：从“要不要做 AI”转向“个人已经变了什么、软件为何先变、企业怎样接住、我作为一把手可以先走哪几条不同的路”。

## Confirmed Presentation Structure

- 全 deck 固定为 14 页；第 1 页是独立标题页，不承担论证，第 14 页是独立 Q&A 收束页，中间保留 12 页主体内容。
- Block 1 占第 1–3 页：第 2 页只画一个人、手里有各种工具、什么都能干；第 3 页只讲第一处断层，不再把杠杆物理做成独立页面。
- Block 2 占第 4–6 页：第 4 页讲观念翻转（年初怀疑、年中转向），突出 Thoughtworks / Fowler 西方圈层和金句；Kent Beck 只钉验证；第 5–6 页再讲工作单元和 `Agent = Model + Harness`。
- 第 7 页单独完成跨行业转场：Coding Agent 正在变成会干活的 Agent。
- Block、Cloudflare、JPMorgan 三个案例已经确认，分别独占第 8、9、10 页。第 8 页 Block 的主画面是三种角色，不是只有 DRI。
- 第 11 页完成跨案例归纳与组织公式；第 12 页给一把手启发和多种入口，第 13 页给学习闭环，第 14 页进入问答。

## Block 1: AI 已经进入个人，为什么还没有进入组织

**Audience Question**: 个人生产力的变化已经肉眼可见，为什么企业层面的价值仍然不清晰？
**Argument Function**: 让听众承认变化已经发生，同时看见第一个断层：个人能力在增长，组织价值却没有自动出现。
**Evidence / Reasoning Beats**:
- 标题页只建立主命题：个人能力跃迁必须被业务连接和组织机制接住，才会成为可持续的 AI 转型；本页不承担主体论证。
- “AI 转型”无处不在，但最先发生的往往不是企业战略，而是一个人工作方式的全面开花。
- 第 2 页只画一个人。WorkBuddy、Cursor、Claude Code、Codex、Trae 是他手里的家伙，不是五个并列主角，也不要一群人各用一个工具。因为工具足够多样，同一个人开始把写代码、写文案、做分析、做创作、做原型串进同一条回路。
- 收束：不是多了一个团队，是同一个人能把整条回路跑完。
- 第 3 页只讲第一处断层：少数人已经闭环，组织还没有提供足够的场景、信心与反馈。个人拿到工具，不等于组织已经获得价值。
- 口播可以保留“遇强则强、遇弱则弱”；不再把杠杆、支点做成单独一页的物理课。公式里的“AI 杠杆”留到第 11 页作为管理用语。
- 软件行业是先锋，因为代码、工具和测试为 AI 提供了结构化上下文、行动能力和快速反馈。
- 转场问题：对软件开发最有话语权的那些人，自己是怎样转过来的？
**Intended Page Range**: 1-3

## Block 2: 软件行业先走了一遍从怀疑到重构的路

**Audience Question**: 为什么 AI 这一次可能不只是又一轮技术热潮？
**Argument Function**: 先用有名有姓的西方软件圈层说明态度确实转了，再用工作单元和 Harness 说明转的是什么。
**Evidence / Reasoning Beats**:
- 第 4 页讲观念翻转，不是会议名录。台上用年初 / 年中：材料是 2026 年 2 月到 6/7 月，口播可说不到半年。突出 Thoughtworks 与 Fowler 的西方圈层；台上的人按西方人来画。
- 年初金句：Fowler “a total, absolute skeptic”；Vella “there is more uncertainty than certainty”。年中金句：“The evidence is in.”“Everybody in the room was shipping it in production.” 中间转折用 Fowler “The game is how fast can we tell whether this is right.”
- Kent Beck 只钉验证：TDD is a superpower with AI agents。半年转向属于 Thoughtworks / Fowler 社区，不能写成 Beck 本人从保守转到拥抱。后面挑战更多。
- 第 5 页：变化的不是模型突然变成员工，而是工作单元逐步变完整：聊天问答 → 小任务协作 → 多步任务执行 → Agent 化工作流。
- 第 6 页：`Agent = Model + Harness`。模型提供理解、推理与生成，Harness 提供上下文、工具、规则、状态、反馈、评估和人工交接。瓶颈从写得快不快，转向多快知道写得对不对。
- 软件行业的启发不是“所有行业都该照搬 Coding Agent”，而是：一旦 AI 能进入完整工作回路，组织的协作边界和验证方式都会变化。
- 转场问题：软件天然拥有代码、工具和测试，其他企业缺少这些条件时，需要重做什么？
**Intended Page Range**: 4-6

## Block 3: 企业必须重做接住 AI 的工作系统

**Audience Question**: 软件行业的变化，与其他知识工作和我们的业务有什么关系？
**Argument Function**: 把软件行业的工作回路变化扩展到企业价值链，说明 AI 转型的真正对象是工作流、责任和组织运营。
**Evidence / Reasoning Beats**:
- 第 7 页不把 Coding Agent 当企业听众已经懂的否定对象。软件里那个很能干的东西，本质是 Agent 在适配人的工作方式：接着干、能改、能反馈，围着人转。
- 企业要接住的是这种会干活的 Agent，不是一个叫 Coding Agent 的产品。回路（目标、推理、执行、反馈、升级、责任）仍在，但是接口，不是整页主角。
- 三个确认案例提供路径互补的组织选择：Block 代表责任角色塌缩，Cloudflare 代表价值链角色重组，JPMorgan 代表核心基础设施与渐进式人才再部署。
- 跨案例共同判断是“重构，不是部署”：个人会用 AI 不等于组织能接住。
- Block 的主画面是三种角色：个人贡献者、DRI、player-coach，不设永久中层。DRI 是其中一种角色，90 天内成为这个问题的 CEO；不是整页只讲 DRI。
- Cloudflare 把人分成 Builders、Sellers、Measurers，并用内部 Cloudflare OS 让非技术部门构建工作流。08 与 09 形成对照：Block 讲责任角色，Cloudflare 讲价值链角色。
- JPMorgan 把 AI 从实验预算重分类为核心基础设施，建设全行 LLM Suite，通过培训、自然流失和再部署逐步改变人才结构。
- 三个案例共同说明：路可以从责任、角色、平台或基础设施开始，但最后都要解决同一组接口问题——人机如何配合，系统之间如何协作，结果由谁负责。
- 转场问题：既然工作流、责任和治理都要改变，谁能为这种改变提供方向、资源和容错？
**Intended Page Range**: 7-10

**Fixed Case Pages**:
- Page 8 — Block：三种角色定位（个人贡献者 / DRI / player-coach），重构责任接口。
- Page 9 — Cloudflare：Builders / Sellers / Measurers，重组价值链角色并建设内部平台。
- Page 10 — JPMorgan：把 AI 作为核心基础设施，渐进重构组织底座。

## Block 4: AI 转型是一把手工程，但不存在标准答案

**Audience Question**: 既然变量这么多，领导者到底应该怎样启动和推进？
**Argument Function**: 把前面三个断层收束为领导者的行动问题：一把手不设计唯一答案，而是创造让有效答案长出来的组织条件。
**Evidence / Reasoning Beats**:
- 组织竞争力可以用一个关系校准：`人才密度 × AI 杠杆 / 组织摩擦`。这里的“AI 杠杆”是管理诊断用语，不是第 3 页的物理比喻。
- `Agent = Model + Harness` 解释协作者如何被造出来；这条组织公式解释协作者如何被组织接住。
- 第 12 页给人启发，不给人唯一处方。当前“一个真实问题、一个完整闭环”只是其中一个建议。其他已经看见的入口包括：先让已经在用 AI 的人被看见；先透明、先做原型，不必先建中台；按公式判断第一刀是缺人才、缺杠杆，还是摩擦太大。
- 第 13 页不再重复启动清单，只回答：无论选哪条入口，都要用探索闭环变成组织学习。真实问题 → 小范围试验 → 形成证据 → 机制化 → 扩大覆盖。成功和失败都必须留下可复用的组织证据。
- 一把手不是挑一个先进案例照抄，而是判断自己的瓶颈究竟在哪里。
- 结尾回到主命题：目标可以一致，路径可以不同；每次探索都在缩短个人能力到组织能力的距离。
**Intended Page Range**: 11-13

## Block 5: 问答 — 把组织问题带回自己的现场

**Audience Question**: 这套判断放回我的组织，最先应该追问什么？
**Argument Function**: 不增加新的结论，把全场命题交还给听众，用开放问答把抽象框架落回具体业务、责任和风险边界。
**Evidence / Reasoning Beats**:
- Q&A 页只承担对话入口：邀请听众带着自己的真实问题进入探索闭环，不新增未经验证的案例、数字或标准答案。
**Intended Page Range**: 14-14
