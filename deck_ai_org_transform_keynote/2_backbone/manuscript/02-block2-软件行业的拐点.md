# Block 2 讲稿素材：软件行业的拐点

> 来源：`../../1_upstream_raw_material/martin-fowler-ai-sdlc-digest.md`；原文回溯：`../../1_upstream_raw_material/source-martin-fowler-ai-sdlc/`

## 从犹豫到下决心

软件行业可能是最早把 AI 杠杆压到完整工作流上的行业。一个很生动的切片是 Martin Fowler 召集的两次 retreat：同一群资深从业者，几个月前还在说“更多的是不确定”，几个月后已经在讨论生产环境、harness engineering、token 经济和风险分层。

这不代表整个行业已经没有问题。它更像一个真实发生的拐点：有些人和团队已经跨过了“要不要用”的门槛，开始研究“怎样稳定地用、怎样判断做对了没有、怎样把成本和风险管住”。

## 能力不是跳变，而是工作单元变了

模型能力可以用四步来讲：

```text
聊天问答 → 小任务协作 → 多步任务执行 → Agent 化工作流
```

一开始，人负责拆解问题，模型负责回答。后来模型开始完成局部任务，再后来，它可以围绕一个目标连续调用工具、保留上下文、根据反馈修正。变化的不是“聊天机器人突然变成了员工”，而是交给系统的工作单元越来越完整。

## Agent = Model + Harness

Agent 不只是一个更大的模型。模型给出理解、推理和生成能力，Harness 把它放进一个真实可工作的环境：它能看到哪些上下文，能调用哪些工具，要遵守哪些规则，产出之后如何测试和评估，遇到高风险动作何时必须请人确认。

所以 Codex、各种 Coding Agent，以及未来的企业 Agent，都可以用同一组问题来理解：它们提供了什么 Harness？让模型看见什么、做什么、如何得到反馈、如何停下来交还给人？

## 关键转折

软件行业真正被改变的，不只是代码生成速度，而是验证回路的速度。问题从“模型能不能写出来”变成“我们多快能知道它写得对不对”。测试、类型检查、静态分析、运行结果和人工审查，都是把自主性变得可靠的 Sensors。

这也是软件经验对其他行业的启发：AI 价值不只来自模型本身，还来自围绕模型搭建的工作环境。
