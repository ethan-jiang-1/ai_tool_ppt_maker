# Martin Fowler AI-SDLC 研究摘要

## 可用故事

Martin Fowler 召集的同一资深从业者社区，约在 5 个月内出现明显的语气转变：

- 2026 年 2 月 Deer Valley：更多的是不确定；Martin Fowler 自称 total, absolute skeptic；AI 被描述为 accelerator，同时也可能成为 debt accelerator。
- 2026 年 4 月：harness engineering 作为术语和实践框架出现，讨论从“模型能不能写代码”转向“我们多快能判断结果是否正确”。
- 2026 年 6/7 月 Engelberg：evidence is in；现场几乎所有人都已在生产环境中使用；讨论进入 harness、token 经济、spec-driven、ephemeral code、risk tiering 和主权等更具体的议题。

这不是两次无关会议的拼接，而是同一召集人、同一邀请制 Open-Space 社区的前后对照，因此可以作为“从犹豫到下决心”的鲜活切片。

## 能力演进的讲法

不要把模型能力简单讲成“从聊天突然跳到 Agent”。更准确的叙事是：模型能力和工作环境一起演进，人的工作单元也随之改变。

```text
聊天问答
  -> 小任务协作
  -> 多步任务执行
  -> 带工具、上下文和验证的自主工作流
  -> Agent 化的组织接口
```

### 1. 聊天问答

模型主要响应人的问题，价值在于解释、生成、改写和头脑风暴。人负责拆题、搬运上下文、判断质量和推进下一步。

### 2. 小任务协作

模型开始嵌入具体工作面：补一段代码、写测试、总结文档、生成方案草稿。人仍然主导任务边界，模型缩短局部执行时间。

### 3. 多步任务执行

人可以把一个更完整的目标交给模型，模型在多个步骤间保持上下文、调用工具并产出中间结果。此时瓶颈从“模型会不会生成”转向“任务是否定义清楚、上下文是否完整、结果如何验证”。

### 4. Agent 化工作流

Agent 不是一个更会聊天的模型，而是模型被放进了一个可以行动、观察、修正和复盘的工作环境。软件开发里，Agent 可能读取代码库、修改文件、运行测试、查看错误、继续迭代，并在边界条件下请求人确认。

## Agent = Model + Harness

本 deck 暂采用这个简化公式：

```text
Agent = Model + Harness
```

其中：

- **Model** 提供语言理解、推理、生成和计划能力。
- **Harness** 是围绕模型搭建的工作环境：上下文、工具权限、规则、任务边界、状态、反馈、测试、评估和人工确认点。

一个更能帮助管理者理解的表达是：模型决定“能不能想出办法”，Harness 决定“能不能在真实环境里稳定地把办法做对”。同一个模型，在不同 Harness 中可能只是聊天助手，也可能成为能修改代码、运行验证、持续修正的工程 Agent。

## Guides 与 Sensors

Martin Fowler 研究中一个值得借用的拆解是：

```text
Harness = Guides + Sensors
```

- **Guides**：行动前的引导，包括任务说明、上下文、约束、规范和可调用工具。
- **Sensors**：行动后的反馈，包括测试、类型检查、linter、SAST、运行结果、评审和 LLM-as-judge。

两者又可以分为：

- **Computational**：确定性检查，如测试、类型系统和静态分析。
- **Inferential**：语义判断，如 LLM 评估、代码审查和结果质量判断。

这解释了为什么软件行业的讨论会从“模型写得快不快”转向“我们多快能知道它写得对不对”。自主性不是把人从环路中拿掉，而是把更多可验证的反馈环路建进工作环境。

## 不同 Harness 的解释方式

不急于把产品名称罗列成竞品表，而是用工作环境的差异来解释：

- IDE 内联补全：模型嵌在编辑器里，Harness 很窄，主要服务局部代码生成。
- Coding Agent：Harness 能读写代码库、调用终端、运行测试和保留任务上下文，工作单元从“补一段代码”扩大到“完成一个变更”。
- Codex 一类的 Agent：Harness 进一步把仓库、命令执行、测试、权限边界和人类交接组织成可重复的工作环境。
- 更广泛的企业 Agent：Harness 还会接入业务知识、内部系统、审批边界、审计和跨团队协作。

因此，用户提到的各种工具不必被解释成“谁的模型更神奇”，而可以放进同一个问题：它们各自提供了什么 Harness，替模型看见什么、能做什么、如何验证、何时停下来请人接管？

## 证据边界

该研究同时提供反证：retreat 社区有早期采用者选择偏差；METR 研究发现资深开发者在特定条件下实际变慢；Stanford 研究显示收益依赖 greenfield/brownfield；MIT NANDA 报告显示多数组织尚无可测 ROI。因此 Block 2 的结论应是“软件行业出现了真实拐点，且拐点的幅度和适用范围仍受 Harness、任务类型和验证能力约束”，而不是“Agent 已经解决软件开发”。
