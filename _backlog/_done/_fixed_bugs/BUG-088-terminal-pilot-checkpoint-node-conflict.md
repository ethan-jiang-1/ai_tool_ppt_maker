# BUG-088: 全失败 Pilot 结束后 checkpoint 与 Controller node 冲突

> 严重级别: P1 | 发现: 2026-08-19 | 状态: 已修复 | 角色: bug | triage: fixed

## 症状

Pure Pilot 的三项都进入 `known_failure` 后，第三次 `image2 generate` 已经写入对应
attempt，但 CLI 随后以内部错误退出：

`target_progressive_checkpoint_node_conflict`

此时 State 仍把 `generate-target-pure-pilot` 标记为 `in_progress`，而 workflow
inspection 已要求 `plan_progressive_pilot`，并说明应选择 successor Pilot scope。
Controller node 与 owner 的下一动作因此互相矛盾，正常的下一次 `generate` 也无法继续。

## 复现

1. 创建一个三页 partial Pure Pilot 并完成授权。
2. 让三次 provider submit 都得到确定的 `known_failure`。
3. 第三次 `ppt_flow image2 generate` 在 attempt 已记录后，以
   `target_progressive_checkpoint_node_conflict` 失败。
4. 运行 `ppt_flow state <run-dir> --json`：当前 node 仍是 generate，primary action
   却是重新 plan Pilot。

## 影响

- 用户没有得到任何 Pilot 图片。
- 当前批次已 terminal，但 Controller 没有进入可以规划 successor Pilot 的一致节点。
- 直接重跑生成会被 checkpoint 冲突拦截；Agent 无法只按一个 owner-issued action 恢复。

## 期望

当 partial Pilot 的所有 item 都 terminal 且无可 review 图片时，第三次 generate 应原子地：

- 记录最后一个 attempt；
- 将 Controller 推进到允许 successor Pilot planning 的节点；
- 返回唯一的 `plan_progressive_pilot` 恢复动作；
- 不把已经持久化的 provider 失败包装成另一个未知内部失败。

## 追加现场（2026-08-19 内容改写后）

同一错误码在**另一次、完全不同的触发**里再次出现，而且这次 owner 工作已经成功落盘。

`deck_ai_org_transform_keynote/3_versions/v1` 在改写 02/04/07 源稿并完成 Style Master
`local-existing` successor 之后：

1. `ppt_flow validate` 正确要求 `image2 plan` 重绑 source/state。
2. `ppt_flow image2 plan` **已经编译出新 plan**（`source_epoch` 前进，
   `provider-input-inspection.json` 里 02/04/07 的 title/body 已是新稿）。
3. 同一条命令随后以 `target_progressive_checkpoint_node_conflict` /
   `category: internal` / `report_internal` 退出码 1。
4. `state --json` 仍显示 `current_node: generate-target-pure-pilot`（`in_progress`），
   而 inspection 的 primary action 是 `plan_progressive_pilot`。

根因与原条目相同：Controller 不允许 `current_node` 回退。源重写后 owner 需要回到
plan/pilot，但 cursor 卡在 generate。`image2.mjs` 在 owner mutation **成功之后**
才调用 `advanceProgressiveControllerCheckpoint`；checkpoint 一失败，整条 CLI 把已经
写好的 plan 包装成未知内部失败。

这比原复现更危险：Agent 若只信退出码，会以为 plan 没做成；若去读 `_generated/`，
会看到新 plan 已经在。退出语义与磁盘事实分裂。

## 期望（补一条）

- 源重写 / Style Master 重绑之后，允许 Controller cursor 回到 owner 当前 checkpoint
  （plan / recommend-pilot），而不是要求它只往前走。
- `image2 plan` 这种零远端 owner 成功，不得因为 checkpoint 回退失败而被报成
  `internal`。要么原子回退 cursor，要么返回 owner 成功并单独标出 Controller 投影失败。
