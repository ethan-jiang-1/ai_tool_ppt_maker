# BUG-092: 已批准的 deck-local 预览图没有进入 PPTX 的合法路径

> 严重级别: P1 | 发现: 2026-08-19 | 状态: 悬挂 | 角色: enhancement | triage: wontfix

## 症状

`deck_ai_org_transform_keynote/3_versions/v1` 在官方 `image2 generate` 走不通
（见 BUG-090：Harness 固定 `generations` + `2000x1125`，本环境可用的是 Packy
`edits` + `2048x1152`）时，只能把成图放进 `_scratch/`。Deck Author 接受这 14 页
视觉并要求“把 PPTX 生产出来”之后：

- `ppt_flow build` / deliver 要求 accepted raw + final manifest，二者都不存在；
- 章程禁止把 `_scratch/` PNG 复制进 `_generated/` 冒充 raw/final evidence；
- 因此**没有一条 owner-issued 命令**能从“人已经接受的预览图”装出 PPTX。

现场只能在 `_scratch/ai_org_transform_keynote.pptx` 另写一份预览装配。它能讲，
但不是 delivery receipt，也不能被 `artifacts` / `build` 认领。

## 复现

1. 确认当前 Image2 transport 无法使用已证明可用的 vendor route（本 deck：Packy edits）。
2. 用 deck-local 预览把全部页出齐，人接受视觉。
3. 运行 `ppt_flow build <run-dir>` 或走 `deliver-target-page-image`。
4. 观察：因 raw 未物化而无法装配；同时没有任何合法命令消费 `_scratch/` 成图。

## 影响

- 视觉已经闭环，交付却断在章程边界上。
- Agent 面对“出 PPTX”只能二选一：空手离开，或违反 `_generated/` 只读/禁手改边界。
- 与 BUG-090 叠加后，整个 Pure 生产在该 vendor 上没有官方终点。

## 期望

二选一即可，但必须有且仅有一条 owner 路径：

- **A.** 官方 generate transport 能打到已声明的 vendor capability（BUG-090 修复后，
  本条自然消失）；或
- **B.** 提供一条显式、人授权的 preview→delivery 装配：只消费当前源绑定的预览图，
  写出带 disclaimer 的 PPTX，**不**伪造 raw acceptance / final manifest。

当前“既不能 generate，也不能合法装配”不是可接受的稳态。

## 修复关联

上游是 BUG-090（transport 到不了可用 route）和 BUG-088（源重写后无法重绑正式
raw lifecycle）。本条钉的是它们在交付层的合流：人已经点头的图，进不了 PPTX。
