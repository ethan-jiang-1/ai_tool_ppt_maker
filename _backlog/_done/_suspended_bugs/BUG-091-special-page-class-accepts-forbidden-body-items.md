# BUG-091: PAGE CLASS 为 opening/transition/closing 时，validate 仍接受 SLIDE BODY

> 严重级别: P2 | 发现: 2026-08-19 | 状态: 悬挂 | 角色: enhancement | triage: wontfix

## 症状

Page Design System 的 `PAGE CLASS OVERRIDE` 规定：`opening` / `transition` /
`closing` 页**不得**加 body cards、diagram、pull quotes、supporting copy 等可读
正文；只保留居中的 kicker/title/subtitle 和一处安静蚀刻。

但 `page_image_source.mjs` 解析 `PAGE CLASS` 后，并不按 class 约束 `SLIDE BODY.items`。
`deck_ai_org_transform_keynote/3_versions/v1` 的 `OrgLink` 曾经同时写着：

- `PAGE CLASS: transition`
- 6 条 `diagram_text` / `supporting_copy` 正文

`ppt_flow validate` 仍报 `source_valid: true`。编译进 provider 的 prompt 因此自相
矛盾：design-system 段落说“不要加 body cards”，同一份 input 里又带着完整回路文案。
出图后就是一张“转场页壳 + 信息页内容”的混杂页。

## 复现

1. 在 Pure `slide-specifications.md` 给某一页写 `PAGE CLASS: transition`。
2. 同一页保留非空 `SLIDE BODY.items`（labels / diagram_text / supporting_copy 均可）。
3. 运行 `ppt_flow validate <run-dir>`：源被判定有效。
4. `image2 plan` 仍会把这些 body items 编进 compiled provider input。

## 影响

- 作者以为选了转场页，实际仍在信息页密度上出图。
- Agent 无法靠 validate 发现“class 与正文冲突”，只能靠事后看图。
- PAGE CLASS OVERRIDE 在编译期被自己的 body schema 抵消。

## 期望

- `opening` / `transition` / `closing` 若带有任何 provider-rendered body item，
  validate 必须在源侧失败，并指出该页的 `PAGE CLASS` 与 `SLIDE BODY`。
- `standard` 页行为不变。
- 不得靠 Agent 事后读 design-system 散文来补这道门。

## 修复关联

源语法在 `ppt_maker_harness/scripts/01-content/internal/page_image_source.mjs`：
`page_class` 被写入 receipt，但 `provider_content` 未按 class 做闭集校验。
`PAGE CLASS OVERRIDE` 只存在于 `page-design-system.md` 散文里。
