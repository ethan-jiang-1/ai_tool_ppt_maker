# 核心隐喻 — 信息加工链（The ITO Chain）

> deck 的身份 DNA 之一。全版本共享，极少变。迁移自 `deck_ai_sdlc_bpm_keynote`。

## 核心隐喻

```
一切白领工作，本质上都是同一条信息加工链：Input → Transformation → Output。
需求进去，代码出来。邮件进去，决策出来。
以前这条链上每个工位都是人。现在 AI 站到了流水线中间——它加工得比人快。
你要么往上游走（决定加工什么），要么往下游走（验收加工结果）。
```

## 为什么是这个隐喻？

它把「软件开发（SDLC）」和「企业业务处理（BPM）」揭示为**同一条链**的两个实例——输入→加工→输出，一个环节的 output 是下一个环节的 input。听众由此得到一个心智模型：AI 不是「更好的工具」，而是接管了链条中段的加工工位，逼迫人向**上游**（定义做什么）或**下游**（验收治理）迁移。

隐喻如何贯穿全场：

| 演讲阶段 | 隐喻怎么展开 |
|---------|-------------|
| Part 0 开场 | 「你公司里每个人都在一条信息加工链上。程序员在，你也在。」 |
| Part 1 软件 | 软件的加工链叫 SDLC——需求→分析→设计→编码→测试→产品。AI 站到了编码和测试的工位上。人被迫往上游（架构、产品）或下游（Harness、验收）迁移 |
| Part 2 企业 | 企业的加工链叫 BPM——业务信息→汇总→分析→审批→决策。跟 SDLC 同一条链。40 年了。AI 正站到同样的工位上 |
| Part 3 组织 | 以前链上每个工位之间需要「信息搬运工」——manager。AI 把搬运成本归零了。金字塔没有存在的理由了 |
| 结尾 | 「你的行业也在这条链上。外面都变了。你在链上往哪走？」 |

## 隐喻的深度：为什么金字塔存在了两千年

ITO Chain 解释了"工作怎么流转"。但它引出一个更深的问题：**为什么组织必须分层？**

答案藏在两个瓶颈里：

### 垂直瓶颈：Dunbar 数的管理版本

一个 manager 能直接有效沟通的人数有上限——大约 7-15 人。所以必须分层：CEO → VP → Director → Manager → IC。每一层的本质功能是**汇总信息、过滤噪音、上传下达**。金字塔不是因为"效率最高"——是因为**人是信息流动的瓶颈，必须用层级管理带宽**。

### 水平瓶颈：知识边界

人是窄域专家——律师不懂工程，工程师不懂财务。所以组织必须分成部门，流程必须在不同专家之间接力。每一个接力点——翻译、对齐、确认——都是摩擦。部门墙不是因为"需要专业化"——是因为**一个人的知识装不下整个业务**。

### AI 同时打破两个瓶颈

回到 slide 05 的那个 Partner：它是一个**通才**（没有专业边界，跨域一步到位），它的**沟通成本接近零**（即时对齐，不需要接力层）。这两个特质——恰好——直接击中了金字塔必须存在的两个理由。

纯粹做信息搬运的中层管理和纯粹跨边界的流程对接——同时失去存在理由。

## 这个隐喻不是什么

不是工厂流水线——是**知识加工链**。每个环节需要判断，不是拧螺丝。但结构是一样的：输入→加工→输出。一个环节的 output 是下一个环节的 input。
