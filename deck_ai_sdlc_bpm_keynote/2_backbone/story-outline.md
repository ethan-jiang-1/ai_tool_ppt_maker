# Story Outline — AI 时代的信息加工变革

## Central Claim

AI 先重构了软件（SDLC），传统企业（BPM）沿同一条信息加工链同构跟进，组织结构因此不可逆地重塑——人要么往上游定义加工什么，要么往下游验收加工结果。

## Audience Outcome

企业管理层 / 决策者听完后，接受"软件只是先行样本、我的行业在同一条链上"，并开始用 Framed Autonomy（人定边界 + AI 在框内执行）重新审视自己组织的岗位与层级。

## Block 1: 封面 — 一句话立题

**Audience Question**: 今天到底要讲什么？
**Argument Function**: 立住主题与基调——这是一场"信息加工方式"的整体重写，不是一次工具升级。
**Evidence / Reasoning Beats**:
- 一切白领工作本质都是同一条信息加工链：Input → Transformation → Output。
- 软件（SDLC）是第一个被掀翻的样本，传统企业（BPM）紧随其后。
**Intended Page Range**: 1-1

## Block 2: 三年加速度 — 这不是 hype

**Audience Question**: AI 到底变了多快？跟我这行有什么关系？
**Argument Function**: 用三年三级跳建立"二阶变化"的感知，把非技术受众从"这是程序员的事"拉进场。
**Evidence / Reasoning Beats**:
- 2024 补全一行代码 → 2025 写完一个函数 → 2026 接管整个项目。
- 软件先被颠覆的两个原因：编译器 0.1 秒反馈 + GitHub 数十亿行代码当教材。
- 同一套 Agent 引擎（Claude Code / Codex Desktop）上午写代码、下午写报告——软件是先行样本。
- 每次技术浪潮给你换工具，这次给你一个通才搭档，但人还没学会协作。
**Intended Page Range**: 2-5

## Block 3: SDLC 被掀翻 — 不是理论，是这五个月

**Audience Question**: 软件开发的方法论真的被颠覆了吗？
**Argument Function**: 用两次 retreat、两位大师和 Fable 5 证明 SDLC 的整个前提（人想、人写、人验）被挖掉。
**Evidence / Reasoning Beats**:
- 旧地图（瀑布 / V 模型 / 敏捷）画的都是"人独自怎么走"，现在多了一个。
- Fowler 两次 retreat（Deer Valley → Engelberg），五个月语调翻转："不是 slides，是 production"。
- Beck + Fowler：AI 的量级大于之前所有变革总和；TDD 变成 non-negotiable。
- Fable 5 让瓶颈第一次从机器变成人——Trust Gap。
**Intended Page Range**: 6-9

## Block 4: 人的角色被重写 — 往两端迁移

**Audience Question**: AI 接管中间加工后，人往哪走？
**Argument Function**: 说明人被挤到信息加工链两端——上游定义什么、下游验收治理。
**Evidence / Reasoning Beats**:
- 信息加工链 7 个节点，AI 通才横跨中间所有环节。
- AI 一晚上写几千行代码，人还是那个速度 review——"Verified" 被重新定义为被测试 / 类型 / 闸门验证过。
- Human-in-the-loop 变 Human-on-the-loop；新工种 Supervisory / Harness / Middle Loop Engineering。
**Intended Page Range**: 10-12

## Block 5: 组织的连锁反应 — 中层与层级

**Audience Question**: 组织会怎么变？谁最危险？
**Argument Function**: 展示中层危机与两种极端重构（Block 一刀切 vs Cloudflare 精准置换）。
**Evidence / Reasoning Beats**:
- Three-Tier Split：初级意外安全、中层真正危机、资深转向架构。
- Block 废掉层级，只留 IC / DRI / Player-Coach；诚实注脚——40% 裁员主因成本削减。
- Cloudflare Builder / Seller / Measurer："displacement, not reduction"。
**Intended Page Range**: 13-15

## Block 6: 换挡 — SDLC → BPM

**Audience Question**: 这跟我的行业有什么关系？
**Argument Function**: 叙事齿轮切换，让受众完成"从程序员到我"的转换，不给新数据。
**Evidence / Reasoning Beats**:
- 软件的故事讲完了，现在轮到你的行业。
- 同一条信息加工链，只是换了名字。
**Intended Page Range**: 16-16

## Block 7: BPM = SDLC 的孪生兄弟

**Audience Question**: 这跟传统企业有什么关系？
**Argument Function**: 建立 SDLC ↔ BPM 同构，证明软件不是特例而是先行样本。
**Evidence / Reasoning Beats**:
- BPM 40 年学术传承（MIT 1980s → Dagstuhl 2026），18 位作者 Agentic BPM Manifesto。
- Framed Autonomy = 人定边界 + Agent 在框内执行；Operational Frame + Normative Frame。
- 企业 IT 四层（前端 / 中端编排 / 后端记录 / 治理）每层都有 SDLC 精确映射。
**Intended Page Range**: 17-19

## Block 8: 真实案例 — 不是 demo

**Audience Question**: 真有传统企业在 production 里做吗？
**Argument Function**: 用两个独立验证案例证明 agentic 重构已上线。
**Evidence / Reasoning Beats**:
- Allianz「Project Nemo」从最窄处跑通再铺开，claims 处理 -80%（诚实注脚：仅 narrow 类别）。
- Maersk 先建数字孪生再让 AI 上船，fuel -9.2%、年省 $300M+（诚实注脚：TradeLens $100M+ 关停）。
**Intended Page Range**: 20-21

## Block 9: 金字塔为什么存在两千年 — 而且为什么结束了

**Audience Question**: 金字塔为什么存在？现在还需要吗？
**Argument Function**: 拔高到组织理论——层级是"人是信息瓶颈"下的不得已，AI 同时打破垂直与水平两个瓶颈。
**Evidence / Reasoning Beats**:
- 垂直瓶颈：Dunbar 数 7-15，manager 是信息搬运工。
- 水平瓶颈：知识边界，部门墙是接力摩擦。
- AI 通才 + 零沟通成本同时击穿二者；纯 relay 中层失去存在理由。
**Intended Page Range**: 22-23

## Block 10: 没有结论，只有一个问题

**Audience Question**: 这一切说明什么？我该怎么办？
**Argument Function**: SDLC / BPM 两条河收敛，把问题抛回观众——不给答案。
**Evidence / Reasoning Beats**:
- 软件的经历 = BPM 的经历，同一套 Agent 基础设施（Claude Code、飞书 / 钉钉 CLI）。
- 纯测量 / 报告 / 协调的岗位不是裁掉，是重新定义（Measurer → AI 异常处理员等）。
**Intended Page Range**: 24-25
