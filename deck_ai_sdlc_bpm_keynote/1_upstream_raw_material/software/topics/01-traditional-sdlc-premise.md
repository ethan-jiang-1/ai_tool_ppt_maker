# 传统 SDLC 的共同前提

> 核心判断：瀑布、V 模型、敏捷——不是三次范式转移。是同一个前提下的三个参数变体。

---

## 传统程序 = 高可靠 + 高确定性

传统程序的本质特征：
- **高可靠**：程序不会自己变，跑 100 次同样的输入产 100 次同样的输出
- **高确定性**：行为可以被完整预期，bug 是人的错误，不是程序的"判断"

这个特征不是缺陷——它是传统软件工程的**地基**。因为这个地基，才有了整个方法论大厦。

---

## 因为程序是确定性的，所以 SDLC 必然是"人先想清楚"

程序不会自己"想"，所以人必须替它想。这个前提贯穿了所有方法论。

```
人想清楚完整需求
    → 分解为模块/组件/函数
        → 逐步实现
            → 验证（是否符合人的预期）
```

---

## 三种方法论 = 三个参数变体

区别只在于：

- **瀑布**：想全部 → 拆全部 → 做全部 → 验全部（一步到位）
- **V 模型**：想全部 → 拆全部 → 做全部，但每个阶段有对应的验证（左右对应）
- **敏捷**：想一点 → 拆一点 → 做一点 → 验一点 → 根据反馈再想（小步快跑）

**关键洞察**：三者不是范式转移的关系。它们是在**同一个前提**（人先想清楚）下的**三个参数变体**：

| 参数 | 瀑布 | V 模型 | 敏捷 |
|------|------|--------|------|
| 拆解粒度 | 全部 | 全部 | 按 sprint |
| 反馈长度 | 项目结束 | 阶段结束 | sprint 结束 |
| 验证手段 | 最终测试 | 阶段验证 | 持续集成 + 回顾 |

**本质上是同一件事的不同节奏。**

---

## AI 改变的不是"怎么想"，是"谁在想"的前提

AI 生成的代码和行为：
- **不是完全确定的**：同一个 prompt 可能产出不同实现
- **不需要人完全想清楚**：人可以给方向、给约束、给验收标准，AI 填中间

这意味着传统 SDLC 的地基被动摇了：
- 如果程序不再是"人完全想清楚"的结果——
- 如果中间层的决策由 AI 做出——
- 那么"需求 → 分解 → 实现 → 验证"这条链需要重新设计

---

## 不是"敏捷的下一步"

AI 时代的 SDLC 不是把 sprint 缩得更短、反馈拉得更快。它是：
- **角色变了**：从"操作者"变成"委托人"（Willison: "I no longer steer; I commission"）
- **瓶颈变了**：从"写得不够快"变成"审不过来"（Fiona Fung: "Build is cheap. Argument is expensive."）
- **质量信号变了**：从"测试覆盖率"变成"有没有人每天用了两周"（Willison）
- **流程的"死者名单"**：PR review、manual user story writing、逐行 code review...（22 条已宣布死亡）
