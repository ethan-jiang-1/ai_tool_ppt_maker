# PART 3: THE BIG PICTURE — Productivity × Communication × Organization

## Block F: 罗马军团散了

---

### S3.1: 以前，人是信息流动的节点——所以必须有层级

**KICKER**: 你们公司的组织架构图——那个金字塔——是罗马军团时代的遗产。

**CLAIM**: 传统组织层级存在的根本原因是**人是信息流动的瓶颈**。信息必须在每个层级被汇总、过滤、再传递。AI 打破了这个前提——当沟通成本降到接近零，中间层的存在理由就消失了。

**BODY**:

为什么公司要有层级？为什么不是 CEO 直接管所有人？

因为**人的沟通带宽有限**。一个 manager 能直接有效沟通的人数有限（Dunbar 数的管理版本——大概 7-15 人）。所以必须分层：CEO → VP → Director → Manager → IC。每一层的作用是汇总信息、过滤噪音、上传下达。

这个结构不是因为"这样效率高"。是因为**人是信息流动的瓶颈，所以必须用层级来管理带宽**。

这是罗马军团时代的组织逻辑。2000 年了，没变过。

AI 打破了这个前提。当 Agent 可以：自动汇总信息、跨层级同步上下文、把沟通从"人→人"变成"人→Agent→人"甚至"Agent→Agent"……中间层的信息中转功能就开始变得多余。

**TRANSITION**: Block 已经在试了——CEO 直接管 6000 人。

### S3.2: 中层如果只做上传下达——没用了

**KICKER**: AI 最根本的组织冲击不在于"裁员"——在于让组织发现哪些层级只做信息搬运。

**CLAIM**: 纯信息搬运的岗位，在 AI 时代没有存在的必要。Block 的 40% 一刀切证明了激进做法的风险，Cloudflare 的 Builder/Seller/Measurer 框架提供了更精确的诊断工具。

**BODY**:

回头看 Block 和 Cloudflare 两条路：

**Block 的教训**：一刀切 40% 裁员的真实动机是成本削减（237% 员工激增后的纠偏），AI 是真实但次要的因素。独立分析师的 AI-washing 检测框架——裁员前员工是否激增？股价是否已承压？是否有运营合规问题？——三个维度全中。最重要的教训：**Klarna 回旋镖**——18 个月前裁 23%，现在后悔。55% 企业后悔 AI 相关裁员，68% 重新招聘。

**Cloudflare 的框架**：Builder/Seller/Measurer 三分法可以直接用于诊断任何组织。

| 角色类型 | 定义 | AI 可替代性 | 你该怎么做 |
|---------|------|-----------|-----------|
| **Builders** | 创造产品的人 | 低 | 保留+扩招，AI 是他们的工具 |
| **Sellers** | 获取客户的人 | 低 | 保留，人际关系不可替代 |
| **Measurers** | 测量、报告、协调的人 | 高 | **不是裁掉——是重新设计：从"做测量的人"变成"管理 AI 测量输出并决策的人"** |

质检员不是被替代——是变成 AI 质检异常处理员。排产员不是被替代——是变成 AI 排产决策审查员。

**三波冲击的时序**：AI 第一波冲击 **productivity**（个人效率），第二波冲击 **communication**（沟通方式），第三波冲击 **organization**（组织架构）。前两波已经在发生，第三波刚刚开始。

**TRANSITION**: 回到最开始的问题——这一切说明了什么？

## Block G: 没有结论，只有一个问题

---

### S3.3: 软件和业务正在同一套基础设施上融合

**KICKER**: SDLC + BPM → 同一个 Agent 界面。

**CLAIM**: 软件研发和业务处理正在被同一套 Agent 工具（Claude Code, Codex Desktop）吸进同一个工作模式。两个领域的边界在消融——不是 future trend，是已经在发生的事。

**BODY**:

回头看一遍。

软件开发经历了什么？SDLC 的前提被挖了。人的角色从操作者变成委托人。方法论转向 Harness Engineering。组织从中层密集转向极端扁平。

企业 BPM 经历了什么？完全一样——Framed Autonomy = AI Sandwich，Agentic BPM = Agentic SDLC。四层架构每层都有精确映射。

**而且，两边现在用同一套工具。** Claude Code 上午写代码，下午写报告。飞书/钉钉的 CLI 化让 office 变成 Agent 的 terminal。这不是"两个领域可以互相借鉴"——这是**两个领域在同一个基础设施上收敛**。

**TRANSITION**: 最后一张 slide。

### S3.4: 外面都变了。你打算怎么变？

**KICKER**: 我今天没有结论。只有一个隐喻。

**CLAIM**: 软件开发行业是煤矿里的金丝雀。它先感觉到了空气的变化。你们——不管在什么行业——呼吸的是同一片空气。

**BODY**:

我今天讲的这些，没有标准答案。

我不知道你的公司应该怎么重组。我不知道你的团队应该怎么重新分工。我不知道 3 年后的组织架构会长什么样。

但我知道一件事。

软件开发行业——地球上最系统化地管理信息加工流程的行业——它的方法论、角色、组织结构，都在 5 个月内被掀翻了。

而你的行业，也在加工信息。

你的公司里，有人在看文档、写邮件、填报表、走审批。这些事——跟写代码一样——都是信息加工。AI 正在学会做所有这些事。

**软件开发是先行样本。你是下一个。**

我今天没有结论。只有一个问题。

外面都变了。听完这些——

**你打算怎么变？**
